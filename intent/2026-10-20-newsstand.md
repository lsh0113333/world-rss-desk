## 문제
"나는 원래 이런 제품만들때 제일 중요한게 단순함이야 정말. 쓰기 편해야해. 딱 봤을때 설명을 안해줘도 뭐 별게없었어요. 걍 보이는게 다라 편했어요. 소리가 나올정도로."
- 지금 앱에는 세계 흐름(AI), 패널, 헤드라인 벽, 보드, 추천, 키워드, Ctrl+K, 바텀 시트가 한데 섞여 있다. 사용자가 직접 써 봐도 구조를 이해하기 어렵다("지금현황 시스템 이해가 잘안가").
- 데이터 경로도 둘이다. 패널은 Vercel이 그때그때 가져오고, 세계 흐름은 GitHub Actions → Supabase로 매시간 가져온다. 그래서 두 화면의 신선도가 다르고, 예약 실행이 안 돌면 세계 흐름이 멈춘다.

## 원하는 결과 (사용자 요구 4가지)
1. "한눈에 바로 보기 좋아야해 편해야해. 빠른시간내에."
2. "대륙 - 나라 - 매체 하이라키를 고집해야해."
3. "무료수준 다 할거야."
4. "지금까지 권한, 시스템 도입한걸 무조건 걷어내자는건 아냐. 먼저 논리적으로 어떤 구상이 좋을지 생각 충분히하고." (엔지니어링 제약은 두지 않는다)

추가 결정 (2026-10-20): "일단 rss만하고 지금처럼 그리고 사용자가 소스를 추가하는 기능은 일단 빼 ai도 다빼"
- 추천 같은 기능은 생각하지 않는다. 카탈로그(270개)만으로 충분하다.

### 화면 구상: 한 페이지 가판대
- 들어오면 설정도 설명도 없이 위에서부터 읽어 내려가기만 하면 된다.
- 상단 고정 바: 서비스 이름, 대륙 바로가기(아시아·유럽·북미·중동·국제·아프리카·중남미·오세아니아), 갱신 시각. 대륙을 누르면 해당 구역으로 스크롤한다.
- 대륙 구역(제목은 스크롤 중 상단에 붙는다) → 나라 카드(국기·이름) → 매체 이름 → 최신 제목 3줄(텍스트 한 줄과 상대 시간).
- 데스크톱은 나라 카드를 신문처럼 3~4단으로 흘려 배치한다. 폰은 같은 순서를 한 단으로 쭉 보여 준다. 탭 바, 사이드 메뉴, 바텀 시트는 없다.
- 제목을 누르면 원문을 새 탭으로 연다.
- 설정 없이 자동으로 되는 것: 지난 방문 이후 새 기사에 파란 점, 읽은 기사는 흐리게, 대륙 접기(접은 상태를 기억).
- 사진은 넣지 않는다. 텍스트만으로 밀도와 속도를 우선한다.

### 시스템 구상
- 페이지를 여는 순간 데이터가 이미 준비돼 있어야 한다.
  - Vercel 서버가 약 10분마다 카탈로그 피드를 한꺼번에 모아 "세계 1면" 결과 하나를 만들어 CDN에 보관한다(stale-while-revalidate).
  - DB와 GitHub Actions는 쓰지 않는다.
- 가능하면 페이지 HTML에 제목을 넣어 보낸다(서버 렌더링). 이것은 CLAUDE.md 규칙 "화면 데이터는 /api JSON으로만"과 부딪히므로 구현 전에 규칙과 ADR을 갱신해 결정한다. JSON API(`/api/front` 등)는 같은 서비스로 유지한다.

### 남길 것 / 걷어낼 것
- **남김**: 카탈로그, RSS 수집·파싱(`services/rss`), url-guard, 매일 피드 상태 점검 cron, 어두운 테마, 읽은 기사 기록(Repository)
- **새로 만듦**: 가판대 페이지, 대륙 바, 새 기사 점, 대륙 접기
- **화면에서 내림**: 보드, 패널·편집기, 온보딩, 직접 RSS 입력·사이트 주소 찾기, 키워드 패널(Google 뉴스)·워치, 추천, Ctrl+K, 오늘의 이슈, 헤드라인 벽, 아래 탭 바, 썸네일, 읽기 모드·원문 서랍
- **보류(지우지 않고 꺼 둠)**: 세계 흐름 AI, Supabase, Gemini, Actions 파이프라인. 가판대가 자리 잡은 뒤 다시 붙일지 따로 정한다.

## 영향받는 사용자·시스템
- 화면: `Dashboard` 전체를 새 페이지로 교체하고, 기존 컴포넌트와 테스트는 대부분 정리한다.
- API: 새 `/api/front`(카탈로그 전체를 대륙/나라/매체 구조로). `/api/feeds`는 피드 점검에 필요한 만큼만 남긴다.
- 저장: `Layout`(보드·패널) 대신 접힌 대륙, 마지막 방문 시각, 읽은 기사만 Repository로 저장한다.
- 문서: PRD, ARCHITECTURE, ADR(새 ADR: 가판대 개편, 렌더링 규칙), UI_GUIDE, CLAUDE.md 규칙 갱신.

## 결정 (2026-10-21, 시안 https://claude.ai/artifact/8pr149sKoEiezyP6eRedEV 를 보며)
- 1차 시안(균일한 카드·목록)은 "좀 별론디" → 2차 디자인 방향 채택: "7개의 대륙 좋아"
  - 대륙마다 고유 색(아시아 주황, 유럽 파랑, 북미 장미, 중남미 노랑, 중동 모래, 아프리카 초록, 오세아니아 청록). 사용자가 색과 디자인을 맡김("너가 사람이 확 눈에 들어올 수 잇게 디자인같은것도 알아서 해봐")
  - 큰 대륙 제목, 나라 바로가기 줄(나라 코드 배지와 현지 시각), 나라마다 가장 최근 제목 하나를 크게(1면) + 매체별 제목 작게
  - 국기 이모지 대신 나라 코드 배지(윈도우에서 국기가 깨지는 문제)
- **"국제 걍 빼버려 대륙이 최상위 레벨로 하자"** → 국제 구역을 없앤다. 묶음 지역(유럽·중동·아시아·중남미·아프리카)도 없애고, 매체는 본사가 있는 나라로 옮긴다. 기준은 "이 매체는 어느 나라의 시각인가".
  - 예: Al Jazeera → 카타르, Arab News → 사우디, Euronews → 프랑스, Politico Europe·EUobserver → 벨기에, Middle East Eye → 영국
  - 이미 그 나라에 있는 매체(DW, Guardian 등)는 합친다. 국제 구역의 IT·과학 전문지, UN News, BBC 지역판, AllAfrica는 뺀다
  - 새로 생기는 나라: 벨기에, 세르비아, 우루과이(카탈로그 country 코드 변경 필요. 피드 id는 바꾸지 않는다)
- 분야 단계는 없애고 매체당 대표 피드 하나만 쓴다(종합 → 국제 → 정치 → … 순서로 고름). 매체당 제목은 3줄, 긴 제목은 2줄까지 보인다
