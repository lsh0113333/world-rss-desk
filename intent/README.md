# intent/ — 만들기 전에 "무엇을, 왜"부터 적는 곳

Anthropic Academy "AI-native SDLC playbook — Capture intent" 방식을 따른다.
아이디어가 기능이 되기 전, **원하는 것·이유·제약을 사용자의 말로** 적은 짧은 문서(`intent.md`)를 먼저 남긴다.

## 흐름
1. **대화**: 사용자가 아이디어를 편하게 말한다. Claude가 범위·사용자·제약·성공 기준을 묻는다.
2. **초안**: Claude가 `TEMPLATE.md` 형식으로 `intent/YYYY-MM-DD-<짧은-이름>.md`를 쓴다 (Status: draft).
3. **수정**: 사용자가 읽고 잘못 이해한 부분을 고친다.
4. **확정**: Status를 `accepted`로 바꿔 커밋한다. 그다음 설계(docs/ADR·ARCHITECTURE) → 테스트 먼저(TDD) → 구현.
5. **완료**: 배포까지 끝나면 Status를 `done`으로 바꾸고 마지막 커밋을 적는다. 하지 않기로 했으면 `dropped`와 이유.

## 규칙
- 기능 하나(또는 한 번에 요청받은 묶음) = 파일 하나. 코드보다 먼저 커밋한다.
- 사용자의 표현을 그대로 인용한다 ("…"). 해석은 따로 적는다.
- 구현 방법은 짧게만. 자세한 설계는 `docs/`에 둔다.
- 구현 중에 의도가 바뀌면 이 파일을 먼저 고친다 (코드가 의도를 따라가게).

## 상태
| 상태 | 뜻 |
|------|----|
| draft | 초안, 사용자 확인 전 |
| accepted | 사용자 확인, 구현 시작 가능 |
| done | 구현·배포 완료 |
| dropped | 하지 않음 (이유 기록) |
