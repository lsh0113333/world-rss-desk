# 우리의 하네스

하네스는 따로 있는 프로그램이 아니라 **AI와 함께 일할 때 맥락을 잃거나 방향이 틀어지지 않게 잡아 주는 작업 틀**이다. 처음 받은 틀에서 쓰는 것만 남기고 우리 방식으로 고쳤다 (2026-11-01, ADR-020).

## 구성

| 구성 | 파일 | 역할 |
|---|---|---|
| 규칙 | [`CLAUDE.md`](../CLAUDE.md) | 항상 지킬 규칙. 대화마다 자동으로 읽힌다 |
| 의도 | [`intent/*.md`](../intent/README.md) | 무엇을 왜 만드는지 사용자의 말로. 확인을 받아야 구현한다 |
| 진행 | [`docs/PROGRESS.md`](PROGRESS.md) | 어디까지 했고 다음에 뭘 하나. 새 대화는 여기서 시작 |
| 안내 | [`docs/GUIDE.md`](GUIDE.md) | 보는 순서, 무엇을 어디서 바꾸나 |
| 설계 | `docs/` 나머지 | 자세한 내용. 목차는 [`README.md`](../README.md) |
| 검사 | 테스트 + `.claude/settings.json` | 응답이 끝날 때마다 린트, 빌드, 테스트 실행. 위험한 명령 차단 |
| 리뷰 | `.claude/commands/review.md` | `/review`로 규칙 준수 점검 |

## 일하는 순서

```
1. 대화    사용자가 원하는 것을 말한다
2. 의도    intent에 사용자의 말로 적고 확인받는다 (accepted)
3. 구현    테스트부터 작성하고 CLAUDE.md 규칙대로 만든다
4. 검사    린트, 빌드, 테스트 통과
5. 배포    GitHub에 올리고 Vercel에 배포한 뒤 실제 사이트에서 확인
6. 기록    PROGRESS 갱신, 이유는 ADR에, 끝난 intent는 삭제
```

## 정책

- **결정은 즉시 기록하고 커밋한다.** 사용자가 "정리"라고 하지 않고 꺼도 다음 대화에서 이어 갈 수 있어야 한다.
- **안 쓰는 것은 남기지 않는다.** 코드, 문서, DB 모두. 기록은 git에 있다.
- **시안은 실제 사이트로 보여 주거나, 어디서 볼지 먼저 묻는다.** 임시 링크를 만들지 않는다.
- **단계 자동 실행기는 쓰지 않는다.** 사람과 대화하며 진행한다.
- **되돌릴 수 없는 일(운영 DB 삭제 등)은 사용자에게 먼저 확인한다.**
