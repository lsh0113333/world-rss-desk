# Architecture Decision Records

## 철학
1인용 MVP. **매일 쓰게 되는 속도**가 최우선이다. 서버 상태 없이 정적 카탈로그, 무상태 프록시, 브라우저 저장소로 구성한다. 의존성은 최소로 두고, 작동하는 가장 단순한 구현을 고른다.

---

### ADR-001: Next.js 15 App Router + Vercel
**결정**: Next.js 15 App Router로 만들고 Vercel에 배포한다. RSS 프록시는 Route Handler(Node.js 런타임)로 구현한다.
**이유**: 브라우저에서 해외 RSS를 직접 받으면 CORS에 막힌다. Route Handler 하나로 프록시, 파싱, CDN 캐시(`s-maxage`)를 한 번에 해결하고, 폰과 PC 어디서나 접속할 수 있다.
**트레이드오프**: Vercel 종속, 서버리스 함수 실행시간 제한. 피드당 타임아웃 8초로 대응한다.

### ADR-002: DB 없이 localStorage + JSON 내보내기
**결정**: 레이아웃(패널 구성)은 브라우저 localStorage에만 저장하고, 기기 간 이동은 JSON 내보내기/가져오기로 한다.
**이유**: 사용자가 1명이라 로그인과 DB는 과하다. 운영비 0원, 개인정보 저장 없음.
**트레이드오프**: 기기 자동 동기화를 포기한다. 브라우저 데이터를 지우면 설정이 사라지므로 내보내기 기능으로 보완한다. 동기화가 필요해지면 ADR-009의 인터페이스 뒤에서 DB 구현체로 교체한다.

### ADR-003: fast-xml-parser로 직접 정규화
**결정**: `rss-parser` 대신 `fast-xml-parser`로 XML을 파싱하고, RSS 2.0, Atom, RDF 정규화는 직접 구현한다.
**이유**: 의존성이 가볍고 Node 내장 모듈에 의존하지 않는다. 매체마다 제각각인 포맷(CDATA, dc:date, Atom link rel)을 직접 통제할 수 있다.
**트레이드오프**: 정규화 코드를 직접 유지보수해야 한다. fixture 테스트로 보완한다.

### ADR-004: SWR로 클라이언트 fetch
**결정**: 패널 데이터는 SWR로 가져온다.
**이유**: dedupe, 포커스 시 재검증, 주기 갱신, 수동 `mutate`를 직접 구현하지 않아도 된다. 패키지가 작다.
**트레이드오프**: TanStack Query 대비 기능이 적지만 이 앱에는 충분하다.

### ADR-005: 피드 카탈로그를 정적 JSON으로 repo에 포함
**결정**: `src/data/catalog.json`에 검증된 피드 목록을 두고, 빌드 시 번들에 포함한다.
**이유**: 버전 관리와 리뷰가 쉽고 런타임 저장소가 필요 없다. 피드 추가는 커밋 한 번이면 된다.
**트레이드오프**: 카탈로그를 바꾸려면 재배포해야 한다. 즉석 추가는 커스텀 URL로 대체한다. 죽은 피드는 `npm run feeds:check`로 주기 점검한다.

### ADR-006: 번역은 MVP에서 제외
**결정**: MVP는 원문 제목만 보여준다. 카탈로그는 영어판 피드를 우선 수록한다(NHK World, DW English, France24 English 등).
**이유**: 번역 API는 키 관리, 비용 한도, 캐시 계층이 필요해 MVP 범위를 키운다.
**트레이드오프**: 비영어권 현지 매체의 시각을 놓친다. 2단계에서 DeepL 무료 API(월 50만 자)로 **제목만** 번역하고 기사 id 기준으로 캐시하는 방향을 검토한다.

### ADR-007: Vitest + Testing Library
**결정**: 테스트 러너는 Vitest(jsdom 환경), 컴포넌트 테스트는 @testing-library/react로 한다.
**이유**: TS/ESM 설정 없이 빠르게 돌고, Jest 호환 API를 쓸 수 있다.
**트레이드오프**: E2E(Playwright)는 MVP에서 제외하고 수동 확인으로 대체한다.

### ADR-008: 커스텀 URL 프록시의 SSRF 방어
**결정**: 커스텀 URL은 `assertSafeUrl`로 검증한다. 프로토콜을 확인하고, DNS를 해석해 사설·루프백·링크로컬·메타데이터 IP를 차단한다. `redirect: 'manual'`로 받아 리다이렉트 대상도 재검증하며 최대 3회까지 따라간다. 요청당 피드 최대 12개, 응답 2MB, 타임아웃 8초.
**이유**: 공개 URL에 배포되는 프록시는 인증이 없으면 내부망 탐색이나 오픈 프록시로 악용될 수 있다.
**트레이드오프**: DNS rebinding을 완벽히 막지는 못한다. 1인용 서비스의 위험 수준에서는 허용한다.

### ADR-009: 확장 대비 — 저장소 인터페이스 + 플랫폼 중립 API
**결정**: (1) 설정 저장은 `LayoutRepository` 인터페이스 뒤에 두고, MVP는 localStorage 구현체만 만든다. (2) 화면 데이터는 전부 `/api/*` JSON으로 받고 Server Action은 쓰지 않는다.
**이유**: 계정 동기화(3단계)와 네이티브 앱(4단계)을 계획하고 있다. 지금 DB를 붙이지 않고도 교체 비용을 "구현체 1개 추가"로 줄일 수 있다.
**트레이드오프**: 지금은 불필요한 Promise 래핑과 인터페이스 계층이 하나 생긴다.

### ADR-010: 앱화의 첫 단계는 PWA
**결정**: MVP에 웹 앱 매니페스트(`app/manifest.ts`)와 아이콘만 넣어 홈 화면 설치를 지원한다. Service Worker와 오프라인 캐시는 넣지 않는다.
**이유**: 코드 추가가 거의 없이 폰에서 앱처럼 쓸 수 있다. 네이티브 앱(Capacitor/React Native)이 정말 필요한지 사용해 보고 판단할 수 있다.
**트레이드오프**: iOS에서는 푸시 알림과 백그라운드 갱신 같은 PWA 기능이 제한된다.

### ADR-012: 원문 보기는 iframe → 읽기 모드 → 새 탭 하이브리드
**결정**: `/api/article`이 기사 페이지를 한 번 받아 X-Frame-Options/CSP를 보고, 허용되면 `frame` 모드(브라우저가 iframe으로 직접 로드), 아니면 `@mozilla/readability` + `linkedom`으로 본문을 추출해 `reader` 모드(블록 JSON), 추출 실패면 `link` 모드를 반환한다.
**이유**: 주요 해외 매체 대부분이 iframe을 막아(33곳 중 약 24곳) 실제 페이지만으로는 기능이 성립하지 않는다. 읽기 모드는 막힌 매체에서도 같은 화면 안에서 읽게 해준다.
**트레이드오프**: 서버가 기사 HTML을 받아오므로 함수 사용량이 늘고(기사 열람 1회 = 1회 실행, CDN 1시간 캐시), 유료벽 기사는 읽을 수 없다. 본문은 개인 열람용으로 저장하지 않으며 항상 원문 링크를 함께 보여준다. `/api/article`도 공개 주소라 남용 시 접근 제한을 추가한다.

### ADR-013: 세계 흐름 분석은 브라우저 안 규칙 기반 + 교체 가능한 엔진 (2026-10-18)
**결정**: 같은 소식 묶기·오늘의 이슈는 `InsightEngine = (items, now) => Insights` 타입의 순수 함수(`ruleEngine`, `src/lib/insights.ts`)로 브라우저에서 계산한다. 제목 키워드(규칙 기반 토큰화, 불용어·한국어 조사 제거) → 대표 기사와 키워드 2개 이상·50% 이상 겹치면 같은 소식 → 2개 이상 매체·나라가 쓰는 키워드를 이슈로, 같은 기사들에 같이 나오는 키워드는 합친다. 추천은 읽기 기록(`ReadEvent`, `ReadHistoryRepository`)으로 7일 반감 가중치 프로필을 만들어 점수를 매긴다.
**이유**: 비용 0원, 서버 저장·개인정보 없음, 화면에 이미 받은 기사만 쓰므로 추가 요청이 없다. 사용자는 2차로 AI(무료 수준)를 붙일 계획이라, 같은 `Insights`를 돌려주는 `/api/insights`로 엔진만 바꿔 끼울 수 있게 타입을 먼저 고정했다.
**트레이드오프**: 형태소 분석·의미 이해가 없어 한국어·영어 기사를 같은 이슈로 묶지 못하고, 흔한 단어가 이슈로 잡힐 수 있다(불용어·최대 비율 25%로 완화). 하루 추세(급상승)는 저장소가 없어 "최근 1시간 기사 수"로 대신한다.

### ADR-014: 원문 보기는 읽기 모드 우선 (ADR-012 수정, 2026-10-18)
**결정**: 판정 순서를 iframe → 읽기 모드 → 새 탭에서 **읽기 모드(본문 추출 성공 시) → iframe → 새 탭**으로 바꾼다. iframe이 허용되면 `embeddable: true`로 "원본 페이지" 전환을 제공한다. 못 여는 기사는 RSS 요약 카드를 보여 준다. 기사 페이지 한도 3MB → 5MB.
**이유**: 서버 판정상 iframe 허용이어도 해외 매체는 쿠키 동의 창·유료벽·frame-busting 스크립트 때문에 브라우저에서 빈 화면이 되기 쉽다(사용자: "기사 눌렀을때 안보이는건 어쩔 수 없나?"). 측정: 매체 82곳 중 서버 판정 실패 8곳(403·유료벽·대용량).
**트레이드오프**: 읽기 모드는 표·영상·인터랙티브 요소가 빠진다 → "원본 페이지" 버튼과 "원문 사이트에서 열기"로 보완. 유료벽 우회는 하지 않는다.

### ADR-011: GitHub + Vercel Git 연동 배포
**결정**: 소스는 GitHub private repo에 두고, Vercel Git 연동으로 push하면 자동 배포되게 한다.
**이유**: 노트북을 꺼도 서비스와 소스가 클라우드에 남는다. preview 배포로 phase별 결과를 폰에서 바로 확인할 수 있다.
**트레이드오프**: GitHub 계정과 Vercel 계정 연결이 필요하다(최초 1회 수동 설정).
