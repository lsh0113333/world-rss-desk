# 설계 결정 기록 (ADR)

**지금 유효한 결정만 남긴다.** 바뀐 결정은 지우고, 옛 기록은 git에서 본다. 번호는 다시 매기지 않는다.

## 철학
**매일 쓰게 되는 단순함**이 최우선이다. 작동하는 가장 단순한 구현을 고르고, 의존성은 최소로, 전부 무료로 둔다.

---

### ADR-001: Next.js 15 App Router + Vercel
**결정**: Next.js 15 App Router로 만들고 Vercel에 배포한다. 화면 API는 Route Handler로 구현한다.
**이유**: API와 CDN 캐시(`s-maxage`)를 한곳에서 해결하고, 폰과 PC 어디서나 접속할 수 있다.
**트레이드오프**: Vercel 종속. 오래 걸리는 수집은 GitHub Actions에서 한다 (ADR-018).

### ADR-003: fast-xml-parser로 직접 정규화
**결정**: `rss-parser` 대신 `fast-xml-parser`로 XML을 파싱하고, RSS 2.0, Atom, RDF 정규화는 직접 구현한다.
**이유**: 의존성이 가볍고 Node 내장 모듈에 의존하지 않는다. 매체마다 제각각인 포맷(CDATA, dc:date, Atom link rel)을 직접 통제할 수 있다.
**트레이드오프**: 정규화 코드를 직접 유지보수해야 한다. fixture 테스트로 보완한다.

### ADR-004: SWR로 클라이언트 fetch
**결정**: 화면 데이터는 SWR로 가져온다.
**이유**: dedupe, 포커스 시 재검증, 주기 갱신, 수동 `mutate`를 직접 구현하지 않아도 된다. 패키지가 작다.
**트레이드오프**: TanStack Query 대비 기능이 적지만 이 앱에는 충분하다.

### ADR-005: 피드 카탈로그를 정적 JSON으로 repo에 포함
**결정**: `src/data/catalog.json`에 검증된 피드 목록을 두고, 빌드 시 번들에 포함한다.
**이유**: 버전 관리와 리뷰가 쉽고 런타임 저장소가 필요 없다. 피드 추가는 커밋 한 번이면 된다.
**트레이드오프**: 카탈로그를 바꾸려면 커밋해야 한다. 죽은 피드는 `npm run feeds:check`로 점검한다.

### ADR-007: Vitest + Testing Library
**결정**: 테스트 러너는 Vitest(jsdom 환경), 컴포넌트 테스트는 @testing-library/react로 한다.
**이유**: TS/ESM 설정 없이 빠르게 돌고, Jest 호환 API를 쓸 수 있다.
**트레이드오프**: E2E(Playwright)는 MVP에서 제외하고 수동 확인으로 대체한다.

### ADR-008: 외부 URL의 SSRF 방어
**결정**: 외부 URL은 `assertSafeUrl`로 검증한다. 프로토콜을 확인하고, DNS를 해석해 사설·루프백·링크로컬·메타데이터 IP를 차단한다. `redirect: 'manual'`로 받아 리다이렉트 대상도 재검증하며 최대 3회까지 따라간다. 요청당 피드 최대 12개, 응답 2MB, 타임아웃 8초.
**이유**: 카탈로그 피드도 리다이렉트로 내부 주소를 가리킬 수 있다.
**트레이드오프**: DNS rebinding을 완벽히 막지는 못한다. 1인용 서비스의 위험 수준에서는 허용한다.

### ADR-009: 확장 대비 — 저장소 인터페이스 + 플랫폼 중립 API
**결정**: (1) 사용자 데이터 저장은 Repository 인터페이스(`BoardPrefsRepository`) 뒤에 두고, 지금은 localStorage 구현체만 만든다. (2) 화면 데이터는 전부 `/api/*` JSON으로 받고 Server Action은 쓰지 않는다.
**이유**: 로그인(로드맵 4단계)과 앱 가능성을 열어 둔다. 지금 DB를 붙이지 않고도 교체 비용을 "구현체 1개 추가"로 줄일 수 있다.
**트레이드오프**: 지금은 불필요한 Promise 래핑과 인터페이스 계층이 하나 생긴다.

### ADR-010: 앱화의 첫 단계는 PWA
**결정**: 웹 앱 매니페스트(`app/manifest.ts`)와 아이콘만 넣어 홈 화면 설치를 지원한다. Service Worker와 오프라인 캐시는 넣지 않는다.
**이유**: 코드 추가가 거의 없이 폰에서 앱처럼 쓸 수 있다. 네이티브 앱(Capacitor/React Native)이 정말 필요한지 사용해 보고 판단할 수 있다.
**트레이드오프**: iOS에서는 푸시 알림과 백그라운드 갱신 같은 PWA 기능이 제한된다.

### ADR-017: 온톨로지 실험실 — 판단은 규칙, AI는 읽기와 말하기 (2026-10-24)
**결정**: 다음 개편은 분야와 무관한 온톨로지 핵심(객체·관계·시간, 정의는 설정 파일) 위에 분야를 꽂는 구조로 간다(세계 뉴스 → "나" → 공공 지원, `intent/2026-10-23-ontology-lab.md`). AI(Gemini)는 기사에서 정해진 유형의 사건·행위자를 **추출**하고 결과를 한 문장으로 **표현**하는 데만 쓰고, 중요도·연관·권고 같은 **판단은 규칙**으로 한다. 모든 결론에는 근거를 붙인다.
**이유**: 사용자 목표는 "엄격한 기준을 통해 딱 이렇게 하심돼요"라는 결과다. 규칙 판단은 같은 입력에 같은 답을 내고 이유를 설명할 수 있다. 핵심을 분야와 무관하게 두어야 세계 뉴스에서 만든 것을 궁극 목표(공공 지원)에서 다시 쓸 수 있다.
**트레이드오프**: 규칙을 사람이 계속 다듬어야 한다. 추출 품질이 전체를 좌우한다(유형 고정, 여러 나라 보도 우선으로 완화).

### ADR-018: 예약 실행은 Supabase pg_cron → GitHub workflow_dispatch (2026-10-24)
**결정**: Supabase pg_cron이 30분마다 pg_net으로 GitHub Actions `workflow_dispatch`를 호출한다(`supabase/migrations/0002_scheduler.sql`). 토큰(fine-grained, 이 저장소 Actions 쓰기만)은 Supabase Vault에 두고 실행할 때 읽는다. GitHub 자체 schedule은 예비로 남긴다(같은 concurrency 그룹이라 겹치지 않음).
**이유**: GitHub schedule은 실제로 3~6시간 간격으로 밀렸다(2026-10-20~21 기록). Vercel Hobby cron은 하루 1회다. pg_cron·pg_net·Vault는 Supabase 무료 플랜에 있다.
**트레이드오프**: 토큰 하나를 사용자가 만들어 넣어야 하고(`scripts/setup-scheduler.sh`), 만료되면 다시 넣어야 한다. 30분마다 쓰기가 생겨 Supabase 7일 비활동 정지도 함께 막는다.

### ADR-019: 첫 화면은 상황판, 점수는 곱하기 (2026-11-01)
**결정**: 첫 화면을 "오늘의 세계"(지금 흐름, 세계 5, IT 5, 대륙별)로 바꾸고 가판대와 `/api/front`를 지운다. 파이프라인이 규칙으로 계산한 상황판 JSON을 `board_snapshots`에 저장하고, 화면은 그것만 읽는다. 점수는 `보도 규모 × 유형 배수 + 떠오름`으로 한다. 제목 단어가 70% 겹치는 사건은 합친다. 스포츠·연예는 유형을 따로 두어 세계 5에서 뺀다. 새 묶음만 AI에 보내고, 기존 사건에 붙는 기사는 규칙으로 처리한다.
**이유**: 사용자가 가판대를 "눈에 안 들어온다"고 했다. 재료가 아니라 답을 보여 줘야 한다. 시안에서 더하기 점수는 나라 수가 다 결정해 스포츠가 1위가 되고 IT 가중치가 무의미했다. 저장해 둔 결과만 읽으면 화면이 빠르고 Vercel 사용량이 적다.
**트레이드오프**: 최대 30분 늦다(무료로는 현실적인 수준). 첫 실행은 묶음이 많아 몇 번 돌아야 다 채워진다. 제목 기준 합치기는 번역 표현이 다르면 놓친다. 사용자별 꾸미기는 없다.

### ADR-020: 단계 자동 실행기를 버리고 우리 하네스로 (2026-11-01)
**결정**: 처음 받은 하네스의 `scripts/execute.py`, `phases/`, `/harness` 명령을 지운다. 규칙(`CLAUDE.md`), 의도(`intent/`), 진행(`PROGRESS.md`), 검사(테스트 + hook)를 남겨 `docs/HARNESS.md`로 정리한다. 함께 지금 코드에서 쓰지 않는 함수와 타입(패널·읽기 모드·이미지 추출·구글 뉴스 처리)을 지운다.
**이유**: 실행기는 처음 이후 쓰지 않았고 사용자와 대화하며 진행하는 방식이 자리 잡았다. 사용자 원칙은 단순함이다.
**트레이드오프**: 자동 일괄 실행이 필요해지면 git 기록에서 되살리거나 새로 만들어야 한다.

### ADR-021: 쓰지 않는 것은 저장소와 DB에서 지운다 (2026-11-01)
**결정**: 끝난 intent, 바뀐 ADR, 옛 DB 테이블(`stories`, `story_*`, `entities`), `articles.image`, 보는 곳이 없는 매일 피드 점검(`/api/feed-health`, Vercel cron, `CRON_SECRET`)을 지운다. 피드 점검은 필요할 때 `npm run feeds:check`로 한다. 끝난 일의 이유는 ADR에, 전체 기록은 git에 남긴다.
**이유**: 사용자 요청 "쓸모없고 안쓰는거 다 날리고". 매니저가 읽을 양이 줄고, 지금 동작과 다른 설명이 남지 않는다.
**트레이드오프**: 옛 AI 요약 데이터는 복구할 수 없다. 죽은 피드는 자동으로 알려 주지 않는다(파이프라인 실행 로그의 실패 수로 본다).

### ADR-022: 내 기준은 브라우저에, 어제 비교는 상황판 기록으로 (2026-11-02)
**결정**: 유형 배수는 `BoardPrefsRepository`로 브라우저에 저장하고 화면에서 순위만 다시 계산한다. 어제 비교는 24시간 전 `board_snapshots`와 규칙으로 계산하고, 그래서 기록을 2일 둔다.
**이유**: 로그인 없이 무료로 바로 쓸 수 있고, 새 테이블이 필요 없다.
**트레이드오프**: 내 기준은 기기마다 따로 저장된다. "어제와 달라진 것"은 기본 기준으로 계산하며, 일별 기록을 오래 쌓는 분석은 아직 못 한다.
